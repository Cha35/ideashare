1
개요 및 BM 연결
왜 만드는가

직관 티켓 외 두 번째 보상 경로로 기프티콘·실물경품을 도입하고, 지급된 경품을 유저가 인앱에서 확인·수령할 수 있는 화면을 정의한다. 보유 경품은 마이 > 내 지갑의 보유 티켓 하단에 노출하고, 수령 진입은 마이 > 내 활동 > 응모 현황 > 경품 응모 및 당첨 알림에서 시작한다.

핵심 원칙 (v1.1)
  • 수령 모델 — 당첨 = 즉시 발급이 아니다. 기프티콘은 발행분 정산 대상이므로, 유저가 [받기]를 클릭한 시점에 발급/코드 할당한다.
  • 진입점 분리 — 수령은 경품 응모 현황 + 당첨 알림에서 시작한다. 내 지갑은 수령 완료된 경품만 노출한다(수령 전 건은 지갑에 넣지 않음).
  • 상세 진입 조건 — 코드(바코드/핀)가 있는 상세는 발급 완료(사용가능) 이후에만 진입한다. 발급 전 '빈 상세'는 존재하지 않는다.
BM 연결
고정 공급되는 직관 티켓은 유저 증가·시즌 종료 국면에서 당첨 희소성이 구조적으로 악화된다. 기프티콘·실물경품은 이 희소성을 분산하는 두 번째 보상 경로로, 픽/응모 지속 동기를 유지 → 광고 노출 방어에 기여한다. 보상 모델 검증 트랙의 인앱 표시 레이어에 해당하므로, 이 화면 자체에는 광고를 삽입하지 않고 마찰 없는 수령 경험을 우선한다.

기프티콘 본인인증 무관 선정 본인인증(미완료 시) → [수령하기] → 즉시 발급·코드 노출 / 제세공과금 시 입금 확인 후 발급 없음 (인증만) · 제세공과금 시 정보 등록(TBD) 사용 유효기간 만료
실물경품 본인인증 무관 선정 개인정보 동의 → 본인인증 → 배송지 입력 (제세공과금 시 입금 확인 후 접수) 배송지 + 동의 이력 · 제세공과금 시 정보 등록(TBD) 배송지 입력 마감 기한
본인인증은 1회 완료 시 계정에 저장되므로(기존 티켓 본인인증 자산 재사용), 재진입 시 게이트를 스킵하고 바로 노출/입력 단계로 진입한다.
만료 개념의 타입 차이 — 기프티콘은 사용 유효기간이지만, 실물경품은 사용 개념이 없으므로 만료는 배송지 입력(접수) 마감 기한으로 정의한다. 접수 완료 후에는 만료 개념이 소멸한다.
수령 모델 (정산 구조 반영) — 당첨 = 즉시 발급이 아니다. 기프티콘은 발행분 정산 대상이므로 무조건 선발급하지 않고, 당첨 알림 → 유저가 [수령하기] 클릭 → 그 시점에 발급/코드 할당한다. 실물경품도 동일하게 [배송지 입력하기] 클릭으로 수령 의사를 받는다. (어드민 PZ는 '발급 예약'만 보유, 실제 발급은 유저 수령 시점)
상태 모델
구분상태값설명
기프티콘수령 대기 확인 중 사용가능 사용완료 만료수령 대기(알림 수신·미수령) → [수령] → 사용가능(코드 발급·노출) → 사용완료(기프티콘 API로 매장 사용 확인) / 만료(유효기간 경과). 확인 중 = 제세공과금 입금 확인 대기. 각주②
실물경품수령 대기 확인 중 접수 완료 만료수령 대기 → [배송지 입력] → 접수 완료 / 마감 기한 경과 = 만료. 제세공과금 발생 시 확인 중(입금 확인 대기)을 거쳐 처리.
각주① 기프티콘 사용완료는 기프티콘 발급사 API 연동으로 매장 실사용 여부를 받아 표기한다(연동 전제).   각주② 기프티콘 확인 중(제세공과금)은 제세공과금이 발생할 만한 고가 기프티콘을 운영하는 경우가 사실상 없어, 정말 예외적인 케이스가 아닌 한 발생하지 않을 것으로 본다. 분기는 정의하되 운영 기본값은 비발생으로 둔다.

수령 동선 · 경품 응모 현황
진입점 · 미당첨 안내 · 받기 → 발급
APP
3-1. 진입점

수령은 내 지갑이 아니라 아래 두 경로에서 시작한다. 내 지갑은 수령 완료분만 보유하므로 수령 전 건의 진입점이 될 수 없다.

진입점역할
당첨 알림(알림톡)발표 시 발송(직관 티켓 패턴 재사용). 당첨 → 받기 동선으로 연결, 미당첨은 중립·재참여 유도 카피.
경품 응모 현황마이 > 내 활동 > 응모 현황 > 경품 응모 탭. 알림을 놓쳐도 결과·수령을 확인하는 영속 화면.
영속성 — 이벤트 페이지(응모하는 곳)는 종료·소멸 가능하지만, 경품 응모 현황은 유저↔응모/당첨 데이터 기반이라 페이지 소멸과 무관하게 내 내역·수령이 유지된다. 정규 경품 응모도 동일 세션 위에 얹는다.
3-2. 경품 응모 현황 화면

위치: 마이 > 내 활동 > 응모 현황 상단에 [직관 티켓 | 경품 응모] 탭 추가(기존 IA·화면 재사용). 데이터 단위는 경품 단위 — 스페셜 응모가 경품별로 응모되므로, 카드 = 내가 응모한 경품 1개.

카드 상태표시액션
발표 대기"○월 ○일 발표 예정" (결과 미정, 중립)없음
미당첨뱃지만 + 카드 딤없음
당첨 · 수령 전당첨 뱃지[경품 받기] → 수령 동선(3-3)
당첨 · 확인 중"입금 확인 중" (제세공과금 O만, 사실상 예외)없음(대기)
당첨 · 수령 완료"수령 완료"지갑에서 확인
'발표 대기' ≠ '확인 중' — 발표 대기는 추첨 전(결과 미정), 확인 중은 당첨 확정 후 제세공과금 입금 대기로 의미가 정반대다. 뱃지 색·카피를 구분한다(발표 대기 amber / 확인 중 purple).

3-3. 수령 동선 (받기 → 발급)
[기본 99% · 기프티콘 · 인증완료 · 5만원 미만] 경품 응모 현황 [경품 받기] 또는 당첨 알림 → 수령 확인 바텀시트("받으시겠어요? 발급 후 취소·교환 불가") → [받기] → 즉시 발급 → 내 지갑에 '사용가능' 편입 → 상세(바코드/핀) 진입 [분기 · 미인증] 위 사이에 본인인증 1회 추가(이후 영구 생략) [분기 · 제세공과금 O] 안내·정보 등록(TBD)·입금 → '확인 중' → 입금 확인 → 발급 ※ 풀스크린 [분기 · 실물] 배송지 입력 → 접수 완료 (제세공과금 O면 입금 확인 거쳐 접수)
수령 확인은 비가역 액션이므로 바텀시트 1회 확인으로 충분(별도 화면·재확인 불필요). 단 제세공과금 O는 정보 등록·입금이라는 실제 절차가 있어 풀스크린으로 처리한다. 발급/코드 할당은 [받기] 시점(제세공과금 시 입금 확인 후)에 확정된다.

4-1. 내 지갑 구성 순서 (변경)
본인인증 배너 → 보유 티켓 → [신설] 보유 경품 → 보유 응모권

기프티콘·실물경품은 별도 섹션을 늘리지 않고 "보유 경품" 단일 영역에 통합하며, 리스트 아이템의 타입 뱃지(기프티콘 / 실물)로 구분한다.

4-2. 노출 범위 · 상태 분기
내 지갑은 수령 완료된 경품만 노출한다. 수령 대기·발표 대기 건은 지갑이 아닌 경품 응모 현황(§3)에서 다룬다. 따라서 지갑 카드는 기프티콘 사용가능/사용완료/만료, 실물 접수 완료(+제세공과금 확인 중) 상태만 존재한다.
상태노출
보유 0건 섹션 헤더 유지 + Empty(타입 A) — "아직 받은 경품이 없어요." (보유 티켓 빈 상태 패턴과 통일)
보유 N건 수령 완료 경품 카드 리스트. 사용가능 상단, 사용완료·만료 하단 정렬.
